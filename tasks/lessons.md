## Règles actives (résumé à relire en début de session)

1. Chercher le code de l'utilisateur (`git status`, diff vs upstream, `find *.be`) **avant** de décrire le dépôt.
2. Lister une arborescence avant de qualifier un dossier ; ne pas extrapoler depuis un seul fichier.
3. Encoder les conventions maison, pas la doc publique.
4. Vérifier le site d'usage avant de déclarer une coquille bugguée.
5. Relire soi-même toute conclusion de sous-agent qui devient une règle.
6. Verrou de fichier sous Windows : **nommer** le détenteur via le Restart Manager, jamais le supposer.
7. **Tout test vert doit prouver quelle ligne l'a rendu vert**, et s'accompagner d'un **témoin** (un cas qui doit échouer). Vaut pour les courses (témoin entrelacé), les exclusions, les filtres et les gardes. Piège tombé 2× le 2026-07-15.
8. Réglage VS Code : identifier le **profil actif** avant d'éditer, et lire le `package.json` de l'extension installée quand un réglage semble inopérant.
9. **Ne jamais dégrader le code de l'utilisateur pour un symptôme que seul mon outillage provoque.** Vérifier d'abord que le problème existe dans SON workflow. Pour surveiller un build en redirigeant la sortie : `PYTHONIOENCODING=utf-8 pio run ... > log` (sinon Python passe en cp1252 et `✔` tue le thread de recopie de pio, ce qui fait perdre TOUTE la sortie).
10. Poursuivre l'observation qui **contredit** l'explication en cours : c'est elle qui tranche.
