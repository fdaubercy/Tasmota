## Compilations de nuit et tâches planifiées (page web)

Tuile « Tâches planifiées » de l'annuaire (groupe Déploiement), page http://127.0.0.1:7920 ; tâche VS Code « Outil : taches planifiees » ou cible Custom détachée. Elle montre et pilote la vérification de nuit que tous les envs perso du fork compilent, par deux voies indépendantes :

- **Sur ce PC** : la tâche Windows `Tasmota-CompilationNuit` lance `maintenance/compilation_nuit.py`, qui passe par la page Build (:7700) avec les actions « compiler » et « construire le FS » et les cases « Publier les fiches QR à la fin » et « Relancer après réparation par l'IA » cochées (jamais de téléversement). Le script démarre la page si elle ne répond pas, ne l'arrête jamais (elle montre encore la série le matin) et attend la fin de la série 24 h au plus ; la série complète (tous les envs du `platformio_tasmota_cenv.ini`, bases comprises : 27 au 2026-11-23, moins `envs_exclus`) dépasse une nuit, la page la mène à son terme et refuse (409) la tâche suivante tant qu'elle tourne. Elle est créée **désactivée**, à 02:00 par défaut (heure réglable depuis la page), sans réveil du PC ni rattrapage (`maintenance/compilation_nuit_tache.py creer|etat|active|desactive|supprime`). Le script refuse de partir si un build tourne déjà (409 de la page Build) ou si un autre `compilation_nuit.py` est vivant (`en_cours.json`), et ne relit que les événements de SA série. Résultats : `%LOCALAPPDATA%\outils_tasmota\compilations_nuit\` (`dernier.json`, `resultat-*.json` sur 30 jours, `config.json` : `actif`, `envs_exclus`, `port`). Codes de sortie : 0 tout compile, 1 échec ou arrêt, 2 refus, 3 désactivé.
- **Sur GitHub** : le workflow `Build_custom` (cron 02:00 UTC, lancement manuel possible). Sa matrice n'est plus écrite à la main : un job `choix` exécute `maintenance/matrice_github.py` (envs du `platformio_tasmota_cenv.ini` moins `outils_docs/compilations_nuit/envs_github.json`).

**Bandeau de santé, recalculé à chaque ouverture** : permissions Actions, état du workflow (`disabled_inactivity`), ancienneté du dernier run planifié (rouge au-delà de 36 h). GitHub désactive les workflows d'un fork après une synchro avec l'amont, et `actions/permissions` répond alors quand même `enabled: true` : le contrôle de l'âge du dernier run est le seul qui le voit. Remède : bouton vert « I understand my workflows, go ahead and re-enable them » sur la page Actions du fork.

**Gestes** (seulement depuis ce PC, en-tête `X-Taches: 1`, jamais avec un jeton distant) : activer ou désactiver, changer l'heure (PC), choisir les envs compilés (une case par env et par voie), lancer maintenant, arrêter. Lancer, arrêter et écrire dans le dépôt demandent deux clics. **Arrêter la voie PC** arrête immédiatement la série en cours de la page Build, y compris au milieu d'un env, **même si elle a été lancée à la main** ; côté GitHub, les runs en cours et en file sont annulés. La sélection GitHub est le fichier `outils_docs/compilations_nuit/envs_github.json` : le bouton « Écrire, commiter et pousser » l'écrit, le commite SEUL (`git commit -- <fichier>`) et pousse ce commit vers `origin/development` (jamais de force). Il refuse, sans rien écrire, si la branche n'est pas `development`, s'il y a des commits non poussés ou en retard sur origin (le push emporterait le travail d'une autre session), ou si le fichier est déjà modifié ; si le push échoue, le commit reste local et le message le dit. Lancer ensuite le workflow. Un env décoché n'est plus compilé la nuit sur la voie concernée.

Limites : GitHub prouve que le code compile avec `platformio_override_sample.ini`, pas que le système de fichiers ni le cache sont ceux du PC ; les gestes n'ont été essayés qu'avec de faux `gh` et `schtasks`. Les safeboot ne sont plus compilés par ce workflow (échec amont `be_constobj.h`). Pas de synchro nocturne du fork, décision du 2026-11-15 : elle reste manuelle.
